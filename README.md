# BE Teammate

A Microsoft Teams bot service on the Claude Agent SDK: bot definitions per tenant, assigned to chats, with a confirmation card before any write. Where it runs, how it is set up and what is open: [docs/handover.md](docs/handover.md).

1. `cp .env.example .env` and fill it in.
2. `docker build -f computer.Dockerfile -t bebotter2-computer .` (the sandbox image for bots with `computer: true`).
3. `docker compose up -d --build` (serves `/api/messages` and `/health` on port 3978).
4. `docker compose exec app pnpm bot-def upsert --tenant <tenantId> --file examples/it-support.json`
5. Message the bot in the chat; the service logs `chat <id> (<type>)` for every message (`docker compose logs app`).
6. `docker compose exec app pnpm bot-def assign --tenant <tenantId> --chat <id> --name it-support`

The admin page is at `/admin`; set `PUBLIC_URL` and `ADMIN_EMAILS` in `.env`.
The Entra app registration needs the Web redirect URI `<PUBLIC_URL>/admin/auth/callback`.
People sync from Microsoft 365 (daily, and from the People screen) needs the Microsoft Graph application permission `User.Read.All` with admin consent.

stdio MCP servers run inside the service container, so install them in the image (the IT Support example's filesystem server is in the Dockerfile).

Bots ask for connections themselves (SSH, HTTP APIs, MCP servers): the bot posts setup steps in the chat, an SSH key is generated by the service, and tokens are pasted through a one-time sign-in link. Credentials stay in the service and never reach a bot's computer. SSH runs from the app container (the image carries `openssh-client`), so targets must be reachable from the host's network, for example over the tailnet. Read-only SSH goes live once verified; everything else waits for an admin or department head to approve it in the chat, and admins can revoke on the Connections screen.

Bots keep shared notes per tenant (the Knowledge screen); notes that look like secrets are refused. Reminders and routines run on cron in the tenant's time zone (set on the admin page); a routine may act unattended only with an admin's grant.
