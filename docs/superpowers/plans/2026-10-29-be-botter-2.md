# BE Botter 2 Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One bot definition, assigned to a Teams chat, answers there through the Claude Agent SDK, runs shell commands on its own container computer, calls the MCP servers it was given, asks for a confirmation card before any write, records every action in an audit trail, and can post to the chat on its own.

**Architecture:** One Node service (Teams gateway on the Microsoft 365 Agents SDK, engine runner on the Claude Agent SDK, Postgres through Drizzle) plus one Docker container per bot definition as its computer, reached over the Docker socket. The engine's permission callback is the single gate: read tools pass, write tools post a card and wait. Audit rows are written before a tool runs and completed after.

**Tech Stack:** Node 24, TypeScript (strict, ESM), pnpm, `@anthropic-ai/claude-agent-sdk` 0.3.312, `@microsoft/agents-hosting` and `@microsoft/agents-hosting-express` 1.9.1, `express` 4, `drizzle-orm` + `drizzle-kit` + `pg`, `@electric-sql/pglite` (tests only), `dockerode`, `zod` 4, `vitest`.

**Spec:** `docs/superpowers/specs/2026-10-29-be-botter-2-design.md`. This plan is the first of four. It covers spec sections 4.1 (tenant, person, chat), 4.2 (definition fields except Graph identity, connections, routines), 4.3 (one role per chat; several roles per chat is plan 4), 4.5, 4.7, 5, 7. Plan 2: personal bot (Teams SSO, Graph MCP server, per-person computers, transcript pruning). Plan 3: connections and routines. Plan 4: admin web page, people and departments, assignments with several roles per chat.

## Global Constraints

- Node 24, pnpm, TypeScript strict, ESM (`"type": "module"`), top-level `import type` only, no inline type imports.
- Package versions pinned exactly: `@anthropic-ai/claude-agent-sdk@0.3.312`, `@microsoft/agents-hosting@1.9.1`, `@microsoft/agents-hosting-express@1.9.1`, `express@4`.
- Claude models only; default model id `claude-haiku-5-5`.
- The words "Claude", "Anthropic" and "Rakazo" never appear in text a Teams user sees. The bot's visible name comes from env `BOT_NAME`, default `BE Bot`.
- No secrets, customer data or real company names in the repo. `.env` is git-ignored; `.env.example` holds placeholders.
- Secrets at rest are encrypted with AES-256-GCM using env `SECRETS_KEY` (32 bytes, base64).
- Migrations are add-only; a later deploy removes what nothing reads.
- Tests are deterministic and offline: Postgres via PGlite in-process, Docker via an injected fake, the Agent SDK via an injected fake `query`. One opt-in integration test may use the real Docker socket when `BEBOTTER_DOCKER_TESTS=1`.
- Modules live in their own folder under `src/`: `config`, `db`, `secrets`, `org`, `bots`, `audit`, `computer`, `engine`, `teams`. No `utils` folder.
- Commits end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>` and `Claude-Session: https://claude.ai/code/session_01WXSYQTnsPU9MujA8sphy99`. Work on branch `feature/core`.

## Review Focus

1. Someone other than the asker clicks "Yes" on a confirmation card: the action stays pending and the clicker is told only the asker can confirm (Task 8).
2. Nobody clicks within 10 minutes: the tool call is denied, the audit row says `expired`, and the bot tells the chat it did not do it (Tasks 8, 9).
3. A message arrives in a chat with no bot assigned: one short reply, no model call, no cost (Task 10).
4. The service restarts mid-conversation: the next message resumes the same engine session, and a click on a card from before the restart gets "This request has expired." (Tasks 8, 9).
5. A shell command on the computer prints megabytes: the tool result is cut to 20,000 characters with a trailing marker so the model and the audit row stay bounded (Task 7).
