# BE Botter 2 Admin Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A small server-rendered admin web page, behind Microsoft Entra sign-in, where admins and department heads manage people, departments, bot definitions, chat assignments and settings, and read the audit trail, replacing the `bot-def` command line for day-to-day use.

**Architecture:** An Express router mounted at `/admin` on the same server and port as the Teams endpoint. Sign-in is the OpenID Connect authorization-code flow with PKCE against the existing Entra app registration; a signed, HTTP-only session cookie carries the signed-in person. Every page is plain HTML built by an escaping template helper, every change is a form POST guarded by a CSRF token, and every query is scoped by tenant and by the actor's role.

**Tech Stack:** Existing stack (Node 24, TypeScript strict ESM, Express 4, Drizzle, PGlite tests, vitest, zod 4) plus `jose` for ID-token validation. No front-end framework, no client-side JavaScript.

**Spec:** `docs/superpowers/specs/2026-10-29-be-botter-2-design.md`, sections 4.1, 4.2 (departments allowed, persona rights), 4.3 (assignments), 4.7 (activity), 4.8 (screens). Plan 2 is the personal bot and Graph, plan 3 connections and routines, plan 5 several roles per chat. This is plan 4 of the sequence, built on `feature/core` (pull request 1).

## Global Constraints

- Node 24, pnpm, TypeScript strict, ESM, top-level `import type` only, no inline type imports. New runtime dependency: `jose` only, pinned exactly.
- Migrations are add-only (new `0001` file generated by `pnpm db:generate`); nothing dropped or renamed.
- Minimal copy. No explainer text, no marketing, no icons. Screens: Bots, People, Departments, Assignments, Activity, Settings, and nothing else.
- The words "Claude", "Anthropic" and "Rakazo" never appear in any page.
- No secrets in pages: MCP header values are never rendered (show "set" or "not set"); the session and CSRF secrets derive from `SECRETS_KEY`.
- Every query is scoped by the actor's `tenantId`. A person never reads or changes another tenant's rows.
- Roles: `user` (no admin access), `head` (head of one or more departments, derived from membership), `admin`. Admins can do everything below; heads see and manage only their own departments; plain users get a 403 page.
- Plain forms only: `POST` with `application/x-www-form-urlencoded`, `303` redirect back to the screen, a hidden `csrf` field verified against the session on every `POST`.
- Cookies: `HttpOnly`, `Secure`, `SameSite=Lax`, `Path=/admin`, eight-hour expiry.
- Tests are deterministic and offline: PGlite for data, injected fakes for the Entra token endpoint and key set, an ephemeral-port server and global `fetch` for HTTP tests (no new test dependency).
- Commits end with the attribution lines of the session reminder in force when the commit is made. Work on branch `feature/admin`.

## Review Focus

1. A signed-in person who is neither admin nor head asks for any admin URL: 403 with no data (Task 3 test).
2. A head asks for, or posts a change to, a person or department outside their own departments, or any row of another tenant: refused, nothing changes (Tasks 2, 4).
3. A `POST` with a missing or wrong CSRF token: 403, nothing changes (Task 4).
4. An admin demotes themselves, or the last admin, to user: refused, at least one admin always remains (Tasks 2, 4).
5. Editing a bot definition without retyping MCP header values keeps the stored encrypted headers, and the page never shows them (Task 5).

### Task 3: Sign-in with Entra and the session

**Files:**
- Create: `src/admin/session.ts`, `src/admin/oidc.ts`, `src/admin/html.ts`, `src/admin/test-server.ts`
- Test: `src/admin/session.test.ts`, `src/admin/oidc.test.ts`, `src/admin/html.test.ts`

**Interfaces:**
- Produces, `html.ts`: `html` tagged template that escapes every interpolated string (`& < > " '`) and joins arrays; `raw(s: string)` marks trusted markup; `layout(opts: { title: string; body: SafeHtml; actor?: Actor }): string` (a complete document with a nav of the six screens limited to what the actor may open, the signed-in name and a sign-out form, and about twenty lines of inline CSS using the system font, monochrome).
- Produces, `session.ts`: `sessionKey(secretsKey: Buffer): Buffer` (HKDF-SHA256, info `"admin-session"`); `signSession(key, payload: { personId: string; tenantId: string; csrf: string; exp: number }): string`; `readSession(key, cookieHeader: string | undefined, now?: number): Session | undefined` (rejects bad signature, expired, malformed); `csrfOk(session, body: Record<string, unknown>): boolean` (constant-time compare of `body.csrf`).
- Produces, `oidc.ts`: `OidcDeps = { db: Db; config: Pick<Config, "teams" | "publicUrl" | "adminEmails" | "secretsKey">; exchangeCode: (code: string, verifier: string, redirectUri: string) => Promise<{ id_token: string }>; verifyIdToken: (idToken: string, nonce: string) => Promise<{ oid: string; tid: string; name: string; email: string }> }`; `oidcRoutes(deps): Router` with `GET /auth/login` (sets a short-lived signed cookie holding state, nonce and the PKCE verifier, redirects to `https://login.microsoftonline.com/<tid>/oauth2/v2.0/authorize` with `scope=openid profile email`, `response_type=code`, `code_challenge_method=S256`), `GET /auth/callback` (checks state, exchanges the code, verifies the token, requires `tid === config.teams.tenantId`, upserts tenant and person from `oid`/`name`, applies `setAdminFromEmail`, loads the actor, refuses with 403 when `!mayEnter`, sets the session cookie, redirects to `/admin`), `POST /auth/logout` (CSRF-checked, clears the cookie). `realOidcDeps(config, db)` builds `exchangeCode` (POST to the tenant token endpoint with the client secret) and `verifyIdToken` (`jose` `createRemoteJWKSet` on `https://login.microsoftonline.com/<tid>/discovery/v2.0/keys`, issuer `https://login.microsoftonline.com/<tid>/v2.0`, audience the client id, nonce check).
- Produces, `test-server.ts`: `serve(app: express.Express): Promise<{ url: string; close(): Promise<void> }>` on port 0.

- [ ] **Step 1: Write the failing tests:** `html` escapes `<script>` and quotes in values and leaves `raw` markup alone; session round-trip, tampered signature rejected, expired rejected, `csrfOk` accepts the right token and rejects a missing one; OIDC through `serve()` with fake `exchangeCode`/`verifyIdToken`: login redirects to the Entra authorize URL carrying a `code_challenge`, callback with a wrong state is 400, callback with a token whose `tid` differs from the app's tenant is 403, callback for an email listed in `adminEmails` creates an admin, sets the cookie and redirects to `/admin`, callback for an ordinary user who heads no department is 403 with no session cookie (**Review Focus 1**).
- [ ] **Step 2: Run to verify failure.**
- [ ] **Step 3: Implement.** Cookie parsing by hand (no `cookie-parser`); the signed login cookie expires in ten minutes; PKCE verifier 32 random bytes base64url.
- [ ] **Step 4: Run to verify pass**, `tsc` clean.
- [ ] **Step 5: Commit** `feat(admin): Entra sign-in, session cookie and page helpers`.
